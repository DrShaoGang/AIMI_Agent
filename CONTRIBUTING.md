# Contributing to AIMI

Thank you for your interest in AIMI. The project is currently establishing its technical and governance foundations. Contribution processes will evolve as implementation begins.

## Ways to contribute

- Report unclear, incomplete, or inconsistent documentation.
- Suggest metadata standards, vocabularies, or evaluation criteria relevant to the architecture.
- Share repository use cases and implementation constraints.
- Propose improvements to governance, provenance, validation, or human-review practices.
- Contribute code after component interfaces and development standards are published.

## Before opening a change

1. Review the project overview and architecture documentation.
2. Keep proposals focused on the stated project scope.
3. Distinguish current implementation from proposed or exploratory capabilities.
4. Avoid including restricted records, credentials, personal data, or confidential institutional information.
5. Document any standards, schemas, or external sources that inform the change.

## Documentation style

- Prefer plain, precise language.
- Define specialized terminology on first use.
- Use descriptive headings and short sections.
- Mark planned features clearly; do not describe them as implemented.
- Preserve provenance for factual claims and evaluation results.

## Code contributions

Technical contribution instructions, testing requirements, and review criteria will be added when the initial implementation is available.
